# Feature Workflow

## General Flow

1. Identify the owner folder before editing: app shell, content, runtime manager, painter, input, UI, or common helper.
2. Add or change content data first. Keep unit/tile/resource/building/hero/quest data in `src/content`.
3. Wire behavior through focused managers or extracted helpers. Avoid adding unrelated branches to `Game`, `UnitManager`, `CanvasRenderer`, `UnitPainter`, or `TilePainter`.
4. Add rendering last, after the state shape is clear.
5. Smoke-test through the real world interaction, not only through syntax checks.

## Add A Resource Or Gatherable

- Put the icon and definition under `src/content/resources/<resource-id>/` and `src/content/resources/definitions.js`.
- Persistent HUD slots are generated by `src/app/shell/createAppShell.js` from resource definitions.
- Spawn and node behavior belongs in `src/gameplay/resources/ResourceNodeManager.js` or a focused manager when the behavior differs from resource nodes.
- Route clicks in `Game.handleTileClick`.
- Add command/update/delivery behavior in unit runtime systems. Extract from `UnitManager` when adding a new behavior family.
- Add marker or carried-load drawing in a focused painter/helper, not directly inside unrelated rendering code.
- Keep depletion, cleanup, reservations, and carried-load fields explicit so workers cannot double-claim nodes.

## Add A Building

- Add content in `src/content/buildings/definitions.js` or a new folder when a building gains local art/logic notes.
- Keep construction cost/effect data in content; construction lifecycle belongs in core/world systems.
- If the building affects roads or build sites, review and consider extracting `Game` road/build helpers.
- If it needs custom visuals, extend tile/building rendering with a focused helper. Painters should not own building rules.

## Add A Unit, Monster, Hero, Or Critter

- Put unit content under `src/content/units/<unit-id>/`.
- Put sprite/spritesheet art and WebP previews under the unit art folder; register runtime sprite/atlas paths in `src/content/assets/runtimeImages.js`.
- Keep shared spawn creation in `src/content/units/spawning` or `_shared`.
- Add behavior in unit runtime systems only when existing orders/patrol/hero activities are insufficient.
- Add sprite manifests beside the unit art. `src/content/units/unitV2Art.js` is a registry, not an art dumping ground.
- For flying units, use `canFly` and path logic instead of weakening ground terrain passability.
- Check spawn distance from camp and biome-specific placement.

## Add Terrain Or Biome Rules

- Put terrain content under `src/content/tiles/<tile-id>/`.
- Update the tile registry and `src/world/createDesertMap.js` biome/type/elevation logic.
- Add tile art beside the tile folder, then teach `TilePainter` or an extracted terrain painter how to draw it.
- Confirm `isTilePassable`, `getTileMovementCost`, and pathfinding still express the intended movement.
- Preserve camp clearing and reachability repair so early play cannot spawn blocked.

## Add UI Or Overlay Behavior

- Static shell markup belongs in `src/app/shell/createAppShell.js`.
- Persistent status behavior belongs in `src/ui`.
- Gameplay modal/card behavior can start in `Game`, but extract it when it grows beyond a small workflow.
- Keep overlays pause-aware through `Game.syncPauseState`.
- Use compact, safe-area-aware CSS in `styles/main.css`.
- Avoid large copy. Prefer icons, short labels, resource pips, progress bars, and in-world markers.

## Add Input Or World Actions

- Change `InputController` only for gesture mechanics or coordinate picking.
- Route clicked tiles through `Game.handleTileClick`.
- Let managers expose `command*` methods for actual actions.
- Add order markers through unit runtime marker helpers.
- Preserve drag/tap thresholds and pinch behavior on touch screens.

## Code Shape

- Prefer extraction before growth in files already above 300-400 lines.
- Keep manager state serializable/plain where practical.
- Avoid hidden coupling through DOM queries outside UI/orchestration classes.
- Keep generated IDs stable and descriptive: `resource-type-index`, `quest-run-n`, `unit-role-name`.
- When mutating tiles, call `world.touchTile(tile)`, `world.touchTerrain(tile)`, or `world.touchStructure(tile)` where cache invalidation depends on world version changes.

## Verification

- Run `node --check` on changed JavaScript files when practical.
- Run `npm run dev`, open the printed local URL, and exercise the edited flow.
- For visual changes, test a wide desktop viewport and a phone-sized viewport.
- For input changes, test mouse drag, wheel zoom, tap/click, touch drag, and pinch when possible.
- Watch the console and the frame monitor.
